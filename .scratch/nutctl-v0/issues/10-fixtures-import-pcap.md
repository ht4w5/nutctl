## Comments

**2026-10-06 — implemented (resolved).** On `main`, next to tickets 01–09 and 12.

- **`nutctl fixtures import-pcap <capture> --model M` (docs/capture.md Method B, `internal/cli/importpcap.go` + `internal/usbmon`)** turns a kernel capture into corpus fixtures. `internal/usbmon` is the capture-format seam (pcap and pcapng containers, the 48- and 64-byte `usbmon_packet` headers of `LINKTYPE_USB_LINUX`/`..._MMAPPED` — pure stdlib, ADR-0006; anything else is refused by name) and hands the importer one HID report per URB (interrupt transfers plus `SET_REPORT`/`GET_REPORT` control transfers; the HID report-id prefix hidraw writes is stripped and counted). `protocol.ParseReport` classifies each report (request / response / the documented 2.4G wake / unparseable / not-this-protocol), and the wire log is grouped by **`protocol.SplitTransfers` — ticket 09's follow-up, exactly as promised** — so one transfer is one fixture in the Method A corpus format (`writeFixtures`, shared with the recorder, keeps the `<case>-2` numbering).
- **Reassembles into framed request/response fixtures** (checkbox 1): pinned by a round trip — a capture synthesized from the committed read-path fixtures' own reports imports back byte-identical fixtures (`TestFixturesImportPcapImportsTheVendorCapture`), including the write path over SET_REPORT/GET_REPORT control transfers and prefixed (report-id) reports.
- **Validation + loud reporting** (checkbox 2): the framing contract is now one function, `protocol.ValidateTransfer` — `corpus_test.go` was refactored onto it, so "imported fixtures validate against the protocol framing" is the same rule the corpus is kept to (not two copies). Exchanges that fail it are **not** imported and are reported with the failure; unparseable traffic is never silently dropped: every capture event ends up either in a fixture or in the traffic report — parse failures are listed with their bytes ("a parse failure is a bug report; keep these bytes!") and fail the exit code, while expected noise (other Devices, key reports on the keyboard's own endpoint, non-report URBs, the 2.4G wake report) is counted and sampled without failing. Device notify traffic (`55 FA`/`55 FC`) imports as response-only fixtures — ticket 08's follow-up gets its notify corpus from captures.
- **Capture provenance in metadata** (checkbox 3): `captureMethod: "usbmon-pcap"` and a `source` naming the pcap file, the Model and its USB ids, the bus/device address, the streams and report length, the capture date and the firmware version where the capture knows one (decoded from the capture's own GET_DEVICE_INFO and cross-checked against `--model`'s USB ids — a capture of another Device is refused, "a fixture whose Device is wrong is not evidence").
- **Key decisions:** (1) `--model` is required — usbmon carries no product strings, and shared product ids mean the capture cannot disambiguate Models on its own (the firmware's name fields never reach a capture), so the operator names the Device and the metadata records it as their claim (docs/capture.md says so); (2) `--usb <bus>.<dev>` picks the Device on a busy bus, refusing ambiguity — never a best guess; (3) parse failures are distinguished from expected noise **by protocol streams** (endpoints/interfaces that carry framing), so a keyboard's key reports cannot become bug reports, at the cost that garbled traffic on a stream that never parses lands in the reported noise bucket (its note says so); (4) only 32/64-byte reports are protocol-shaped (docs/protocol.md §1/§6.5) — other sizes are reported traffic, and the set extends when a capture shows evidence; (5) the corpus test learned requestless and UNPARSED exchanges (recorded-as-observed), which the ticket 09 recorder already writes — without that, committing notify fixtures breaks the suite.
- **Testing (the agreed seams):** the capture format at `internal/usbmon` (capture bytes built literally — pcap and pcapng, both header sizes, `if_tsresol`, refusals), the protocol seam (`ParseReport`, `ValidateTransfer`, `TransferName`), and the CLI surface end to end (capture file in → corpus fixtures + traffic report out, refusals, `--usb`, usage errors). Full suite green, `-race` clean.
