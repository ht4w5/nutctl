**Blocked by:** 05

**Status:** resolved

- [x] Base Layer and Fn Layer toggle in place
- [x] The Knob's three gestures (clockwise, press, counter-clockwise) appear as rows like any Key Slot
- [x] The rebind picker offers keyboard keys, consumer/media keys, mouse buttons, and Functions

## Comments

**2026-10-05 — implemented (resolved).** On `main`, next to tickets 01–05.

- **The Keys screen** (`internal/tui/keys.go`): the table is the Model's layout table rendered over the session's edit buffer — 87 physical keys in display order plus the Knob's three gestures as rows like any Key Slot (named `knob clockwise` / `knob press` / `knob counter-clockwise`: the gesture IS the physical thing, and the acceptance's own words; the CLI keeps its name+gesture spelling `Volume Up (knob clockwise)`), beside a static ASCII TKL map (`keysMap` — truly static per spec user story 9: it reflects neither cursor, Layer nor edits; labels follow the layout table's names in short form). The 90-row table scrolls in a 20-row window (↑/↓, pgup/pgdn), `space` toggles the Base Layer and the Fn Layer **in place** (cursor and edits stay where they were), and `*` marks every row whose shown Key Action differs from the Device — the same truth the status bar's pending line states. The table is a physical view: the firmware-matrix extraSlots have no key to find and stay the CLI's `nutctl get keymap` listing (deliberate — see suppressions).
- **The rebind picker** (`internal/tui/bind.go`): `enter` on a row opens one more mode of the keyboard (like the path prompts and the write gate) offering the four kinds of Key Action CONTEXT.md names — **keyboard key** (107), **consumer key** (17), **mouse button** (7), **Function** (287) — with ←/→ switching kind, ↑/↓ moving, and type-to-filter finding one entry among 287 Functions. `enter` binds into the local edit buffer only (the wire hears about it only through `a`), `esc` changes nothing.
- **The Key Action catalog is data** (`internal/protocol/catalog.json`, `catalog.go`): extracted verbatim from the bundle's own picker tables (`basicChars` Pn + `extendChars` Un, `specialChars` so, `funcChars` Ko) with English names from its locale — provenance in the file's `source` field and `docs/protocol.md` §4 (which also corrects the Ko table's size: **287 entries**, values 1..287, not the 77 the docs previously claimed). Wire encodings are pinned to the bundle's own `lo()` writer by test: `02 00 <code> 00`, `03 <usage LE16> 00`, `01 <axis> <value> 00`, `0d <id BE24>`. A future Model with a different Function table becomes a data file; macros/advanced keys extend the same catalog with their kinds.
- **One spelling of a Key Action** (`protocol.KeyActionText`): a catalog entry renders as `keyboard key "Esc"` / `consumer key "Volume +"` / `mouse button "Left mouse button"` / `Function "Restore Factory Settings"` — the words the picker offers it under — used by the table, the picker header, the pending line, the read-back diff **and** `nutctl get keymap` (its human output changes accordingly; `--json`, the stable scripting surface, is untouched). Naming is exact: a Key Action is named only when all four wire bytes match a catalog entry, so names never collide and a diff of names never hides a byte difference; everything else stays visible as its raw form (`KEYBOARD(01 29 00)`, `UNKNOWN(...)`).
- **Fn-disabled Key Slots** (the layout table's `fnDisabledSlots`, the vendor config's `fnDisabledKeyIds:[1..12]`): marked `(fn-disabled)` on the Fn Layer (the CLI's spelling) and unbindable there — `enter` refuses with `refusing to rebind Key Slot 1 (F1) on the Fn Layer: Fn-disabled in the Model's layout table` and the picker never opens. On the Base Layer the same Key Slot rebinds: the restriction is the Fn Layer's (spec user story 15), exactly what the table marks.
- **Remaps ride the shared edit mechanics of ticket 05** (edit.go/write.go): the pending line names the change in the picker's words (`base Key Slot 0 (Esc): keyboard key "Esc" → keyboard key "L-Ctrl"`), `a` writes **only the edited Layer's block** — a Base remap sends SET_KEY and never SET_FN_KEY, pinned byte-for-byte at slot 0 (`02 00 e0 00`) while untouched slots keep the Device's bytes — through the write gate and read-back verification, and `r` reverts without wire traffic. The State File round-trip is pinned end to end: apply on one fake Device → save → `load` onto a second → the same four bytes reach the wire again and verify.
- **The round-trip test found a real bug (fixed here):** `write.go`'s `updateRefreshed` rebased the queued write's payload onto the edit buffer for *every* write at the gate — including a **load**, whose payload is the State File. Whenever file ≠ device state, a load wrote the gate's fresh read instead of the file. Now an apply's payload is the rebased edits and a load writes the State File byte for byte, exactly as `nutctl load` writes it (ticket 03).
- **Testing (both agreed seams):** `internal/tui/keys_test.go` drives whole sessions with key messages against the fake Device — golden frames (the table + map on both Layers, the picker, the filtered picker, the Knob rows), wire assertions (the SET payload bytes, only the edited block out, no wire for bind/revert/refusals), and the State File round trip; `internal/protocol/catalog_test.go` pins the constructors' wire bytes and the exact-match naming at the protocol seam (same domain-function precedent as `RunChecks`/`Identify`). The full suite is green; `internal/cli`'s `get keymap` goldens updated for the named rendering only.

**Code review (two-axis, post-implementation):** fixed the Standards findings — vocabulary drift (the picker's "family"/"group" wording replaced by CONTEXT.md's own Key Action vocabulary `keyboard key / consumer key / mouse button / Function`, one spelling shared by the picker's kind bar and `KeyActionText`; `ActionGroup` → `ActionKind`) and the smell calls (the layer→keymap selection repeated in four call sites → `keyLayer.keymap`; cursor clamping and window scrolling hand-rolled twice → `clampRow`/`keepVisible` shared by table and picker; `bindState` copying the `slot, name` clump → it carries the `keyRow`; the picker's clip width reused `keyMapX` → its own `bindNameW`). **Suppressed findings (deliberate):** `MouseButton(axis, value byte)`'s "value" (CONTEXT.md's Avoid is scoped to Key Slot; `value` is the name docs/protocol.md §4's MOUSE row gives the wire byte); the table listing physical keys + Knob and not the firmware-matrix extraSlots (spec story 11's "any Key Slot" — those slots have no physical key to find or press, and `nutctl get keymap` lists all 128 for completeness); the load-payload fix living in this ticket (its State File round-trip acceptance cannot pass without it); `KeyActionText` renaming CLI human output (deliberate one-spelling unification; story 31 pins only `--json`); the picker's type-to-filter (287 Functions are unusable by scrolling alone); the Functions kind offering "Restore Factory Settings" (story 27 is about the tool's own reset *action* behind typed confirmation — binding a key is the user's explicit choice, and the firmware itself binds that Function to Fn+Esc, so hiding it would forbid restoring the default).
